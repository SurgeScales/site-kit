# UX laws

Every screen maps to these ten laws. Each row gives the concrete rule to implement, not the theory behind it.

| Law | Objective | Implementation rule |
| --- | --- | --- |
| **Aesthetic-usability effect** | Perceived quality raises perceived usability. | Tight, consistent spacing tokens, one type ramp, and hairline separators. No decorative clutter. |
| **Hick's law** | Fewer choices mean faster decisions. | Collapse filters, advanced options, and long lists behind toggles or "Show N more". Advanced panels start collapsed. |
| **Jakob's law** | People expect sites to work like other sites. | Top navbar, left drawer, right inspector, standard modals, standard status text, familiar icon groups. |
| **Fitts's law** | Targets should be fast to hit. | Primary actions are large (44px or taller), high-contrast, and placed where the eye lands after reading. Icon targets get real padding. |
| **Law of proximity** | Related things belong together. | Group related inputs and information with space and one container, not with extra boxes. |
| **Zeigarnik effect** | Unfinished tasks pull people back. | Show progress on multi-step flows ("Step 2 of 4" plus a bar). Always show save state: "Saving…", "Unsaved changes". |
| **Goal-gradient effect** | People speed up near the finish. | Pre-fill the progress bar for the current step. Make the "next step" button the most saturated element on the screen. |
| **Law of similarity** | Things that look alike should behave alike. | Every repeated control (toggle, select, row action, chip) shares size, padding, hover state, and icon style on every page. |
| **Miller's law** | Working memory holds about 7 ± 2 chunks. | At most about seven visible choices on one layer. Split long configuration into steps or tabs. |
| **Doherty threshold** | Feedback must arrive within 400ms. | Skeletons for data areas, optimistic toggles, and immediate pressed and loading states on every async action. |
